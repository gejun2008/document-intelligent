# 长文档 OCR：兼顾表格准确性与处理延迟的通用方案

> 状态：待评审。适用于长 PDF、扫描件及混合版式文档，不绑定特定仓库、编程语言或 OCR / Auto Layout 服务。本文是设计方案，不代表已实现或已验证的效果。

## 1. 问题与目标

长文档整份识别容易遇到请求上限、超时和长尾延迟；固定页数切块虽然便于并发，却可能切断跨页表格。固定 overlap 会增加重复计算，也无法独立解决复杂表格的关联与恢复问题。

目标是在资源和时延预算内提高自动解析覆盖率，保留表格内容、行列关系及来源；无法确认的结构明确标记，避免静默误合并或删改。

**核心策略：先识别跨页表候选，优先沿安全边界切分；识别后进行全局校验，只对疑难区域补充上下文并重解析。**

“同块解析”可以减少切分引入的损坏，但不能保证引擎自动输出完整逻辑表。准确性仍需要结构校验、可追溯结果与异常处理共同保障。

## 2. 总体流程

```text
文档接入与资源检查
    ↓
轻量预扫：原生信息复用 + 必要的视觉检测
    ↓
相邻页候选关联与边界分级
    ↓
资源约束下的安全切块
    ↓
受控并发识别与块级失败隔离
    ↓
统一结构表示 + 块内 / 块间全局校验
    ├─ 结果可信 → 确认输出
    ├─ 存在歧义 → 局部扩大上下文重解析 → 再次校验
    └─ 预算耗尽或仍不确定 → 保留原片段、风险标记与人工复核
```

短文档可在资源允许、整份路径已验证稳定时跳过完整预扫，直接识别并校验。具体路由由目标服务与业务样本决定。

## 3. 两级预扫与跨页候选识别

### 3.1 第一级：获取粗粒度版式

按页受控并发，获取页面尺寸、方向、表格候选区域及其位置。可信的原生文本和几何信息优先复用；扫描件使用轻量视觉版面检测。

表格外框检测不等于内部结构识别。低分辨率下无法可靠确定的列数、列边界、表头角色标记为 unknown，不得将检测失败解释为“无表格”。

### 3.2 第二级：只补查疑难边界

对疑似跨页关系提高局部检测分辨率，必要时识别少量表标题、表头或续表标记。避免在预扫阶段对所有页面执行完整 OCR 或高成本视觉模型调用。

预扫耗时必须计入最终延迟。检测模型、渲染参数及结果可缓存；模型不可用或检测失败时进入显式降级路径。

### 3.3 以表区域建立候选关系

跨页判定同时使用多类证据：

| 证据类型 | 示例 |
|---|---|
| 几何 | 页尾 / 次页页首位置、归一化宽度、列边界对齐 |
| 结构 | 多级表头、列映射、合并单元格、重复表头 |
| 内容 | 表编号、“续表”、行序号及上下文延续 |
| 反向证据 | 新表标题、新章节、不同列语义、明确结束标记 |

贴边、相同列数或相似表头都只能作为证据，不能单独决定合并。列数不同也不能直接否定续表，因为结构检测可能受到跨列单元格等因素影响。

关系关联到具体表区域，支持一页多表。按原始页号判断邻接，不能因为路由过滤或缓存命中，把不连续的页面当成相邻页。

每个页缝分为三态：

- **continuation**：高可信存在跨页表，应尽量避免切分。
- **safe**：有足够证据支持切分，优先作为切点。
- **uncertain**：证据不足或冲突，先按预算补查，仍不确定时保守调度。

“放入同一块”是调度决定，不等于认定两段属于同一张逻辑表。

## 4. 资源约束下的安全切块

切块同时考虑两类约束：

| 类型 | 内容 | 处理方式 |
|---|---|---|
| 软目标 | 期望页数、预计耗时、负载均衡 | 可为保护表链适度突破 |
| 硬上限 | 服务页数 / 字节限制、内存、像素量、请求超时预算 | 提交前检查，不得突破 |

优先在安全页缝切分；在合理范围内移动切点，保护续表链。块大小根据页面复杂度和实测服务延迟调优，不以固定页数作为正确性条件。

每块记录原始页映射、负责输出的页面、仅提供上下文的页面，以及切分理由。混合原生解析与 OCR 时仍保留必要的相邻上下文。

### 超长表处理

- 表链在硬上限内：可作为独立块联合解析。
- 表链超过硬上限：受控拆分，按需加入 overlap，再恢复全局表格关系。
- 无法确认恢复结果：保留片段和候选关系，标记复核。

常规安全切块不固定加 overlap。overlap 仅用于无法避开的风险边界或局部重解析；输出按页面 / 区域归属去重，不能按文字相同就删除合法重复行。

整份文档都是一张长表时，可能无法获得明显的并发收益，也不能保证整份解析成功；应如实报告适用边界。

## 5. 受控并发与失败隔离

限制并发请求、排队任务和在途数据量，避免增加并发反而触发限流与长尾。

| 失败类型 | 建议动作 |
|---|---|
| 限流 | 遵守服务退避要求，降低请求压力 |
| 临时网络错误 / 服务端错误 | 有限重试，设置总预算 |
| 请求过大 / 持续超时 | 缩小分块，优先寻找安全边界 |
| 不可重试错误 | 记录失败，保留其他块结果 |
| 返回页数 / 映射异常 | 显式报错，禁止静默截断或遗漏 |

失败缩块不能机械二分切断已识别的表链；无法避开时进入受控断表恢复路径。

单块失败不要求整份重跑。成功结果持久化，文档可呈现“部分完成 / 需复核”；最终状态必须反映未完成部分。

## 6. 结构保留、全局校验与局部重解析

### 6.1 统一结构表示

识别结果至少保留：

- 原始块结果与版本。
- 页面、区域和阅读顺序。
- 表格片段、行列索引、rowspan / colspan、单元格内容。
- 原始页号、坐标及可用的文本位置映射。
- 候选续表关系、合并依据、确认状态与风险原因。

避免将逐页切开的 Markdown 作为唯一结果。复杂表格可以用 HTML 展示，并用独立结构化结果保存完整关系和来源。

### 6.2 全局校验

覆盖同块内、跨块间，以及混合引擎输出中的候选续表。即使一个请求包含整条表链，也必须检查服务是否仍将其拆成多张表。

同时判断：

1. 两个片段是否属于同一张表。
2. 列、行、表头与断行如何正确映射。
3. 合并后是否丢失、重复或错置内容。

只在证据充分且结构校验通过时自动合并。去除重复表头和页眉页脚需有位置、角色与一致性证据，不能误删分组标题或合法数据。

合并和展示去重可追溯、可撤销。模型可辅助关联与映射，不得为了补齐表格而生成缺失单元格内容。

### 6.3 有界局部重解析

对不确定表格增加必要的相邻页或表格上下文，重新识别后再次校验；具体上下文形式取决于引擎能力，不能裁掉恢复结构所需的信息。

限制每份文档的补算页数、重解析轮数、额外调用量和总耗时。预算耗尽后保留原始片段，输出风险代码、来源页、原因和候选关系，例如：

```text
status: needs_review
reason: cross_page_table_unmerged
source_pages: [12, 13]
```

风险必须进入结构化输出，不能只写日志。已确认结果可以先行返回，未确认表格保持待处理或待复核状态；用于计算或入库时，由业务规则决定是否允许消费。

## 7. 缓存、恢复与可观测性

受上下文影响的识别结果不能只按“文件 + 页号”缓存。缓存依赖应覆盖文档内容、原始页映射、上下文范围、引擎 / 模型版本，以及检测、切分和恢复配置版本。

分别保存预扫、识别和结构恢复结果。上下文或版本变化时使相关结果失效；失败恢复复用成功结果，必要补算的原因和用量必须可见。

监控至少包含：

- 预扫、排队、识别、校验与重解析耗时。
- 成功率、部分失败率、重试次数与复核率。
- 原始页数、实际处理页数及重复处理占比。
- 请求数、模型用量与可获得的费用信息。

实际重复处理的 overlap 页计入算力和服务用量；同一次调用的用量不能重复汇总。

## 8. 业务模式

| 模式 | 策略 | 典型用途 |
|---|---|---|
| stable | 准确优先，更充分的校验与补算预算；未确认表格阻止自动消费 | 财务、合同、结构化入库 |
| balanced（建议默认） | 安全切块并发、按需 overlap、全局校验、有界重解析 | 通用长文档 |
| fast | 减少补算，优先快速获取文本；发现表格风险时升级处理或明确标记 | 搜索索引、预览、文本提取 |

stable 不等于无上限整份请求，fast 不等于可以静默损坏表格。短文档阈值、块大小、并发量和补算预算均根据服务能力与业务目标配置。

## 9. 验证与验收

### 测试集

建立具有独立金标的真实样本与可复现合成样本，覆盖：

- 两页及多页长表、超长表。
- 无框表、多级表头、合并单元格和跨页断行。
- 同模板独立表、新表标题、一页多表等误合并负例。
- 页眉页脚、重复表头、分组标题、合法重复行。
- 扫描偏移、旋转、低清晰度和页面尺寸变化。
- 预扫漏判 / 误判、块内断表、混合路由和部分缓存。
- 服务限流、超时、超大请求、结果缺页与补算预算耗尽。

确定性测试验证编排、边界处理和数据完整性；真实服务测试验证实际识别质量与性能。模拟结果不能代替真实 OCR 效果。

### 对照评测

使用固定文档清单，对比整份解析、固定分段及本方案。保持模型版本、渲染参数、服务区域、配额与资源预算一致，冷缓存与热缓存分别报告。

端到端延迟包含预扫、排队、重试、全局校验和局部重解析。超限与超时计入失败统计，不能仅用成功样本声称整体达标。

| 维度 | 指标 |
|---|---|
| 表格质量 | TEDS、单元格内容 F1、行列和跨度准确性 |
| 跨页关系 | 同表关联 precision / recall / F1、误合并率 |
| 数据完整性 | 漏页、重复页、缺行、重复行、来源可追溯性 |
| 自动化程度 | 自动通过覆盖率、人工复核率 |
| 延迟 | 首批可用时间、最终结构确认时间 P50 / P95 |
| 成本与可靠性 | 实际处理页数、调用量、费用、成功及部分失败率 |

TEDS 等指标须注明表配对和规范化规则；未合并或交人工的表格不能算自动恢复成功。

### 验收原则

先依据业务风险冻结准确性门槛，再确定延迟、成本和复核率目标；数值由基线与代表性样本确定，本文不预设加速比例或准确率承诺。

验收至少要求：

- 确定性正负例通过，不出现静默丢页、删行和误合并。
- 真实评测满足约定质量门槛，并在可比条件下达到延迟目标。
- 同时报告自动通过覆盖率和复核率，避免把问题转交人工后宣称准确率提升。
- 按文档类型、表复杂度和表链长度报告效果与限制。
- 未完成真实验证的项目标为未验证，不计为通过。

## 10. 建议落地顺序

1. 固定评测口径、代表性样本和基线。
2. 建立结构化结果、原始页映射与来源追溯。
3. 实现预扫、边界分级与受资源约束的安全切块。
4. 接入受控并发、分类重试与成功结果恢复。
5. 实现全局校验、按需 overlap 和局部重解析。
6. 完成风险输出、业务模式和缓存依赖管理。
7. 进行真实质量 / 性能对照，按结果调优并确认验收。
