# LLM 纠错请求优化方案：错误摘要、显式预算与分批降级

> 通用设计方案，不绑定特定项目或模型。本文仅描述后续优化方向，不代表已实现或已验证。

## 目标

控制纠错请求膨胀，避免首轮请求未超限、纠错请求因附带完整失败响应而超限；保留已通过校验的结果，并补齐可观测性。

## 1. 纠错只回传错误摘要，不回传整份响应（优先实施）

将失败响应压缩为结构化错误信息：

- 哪些引用校验失败。
- 每处失败原因。
- 涉及的条款编号。

摘要以精简为原则，通常可控制在几百字符，但实际大小须服从请求预算。模型重新生成时使用原始证据和错误摘要，不再附带上次完整输出。

## 2. 为纠错阶段设置显式预算（优先实施）

- 首轮请求预留固定比例的余量，例如输入预算不超过可用上限的 70%；具体比例可配置。
- 纠错阶段发送前，检查原始请求、错误摘要及纠错指令的总量，确保不超过预算。
- 超出预算时按优先级裁剪：先精简错误摘要细节，再移除低相关证据片段，绝不裁剪校验要求。
- 若仍无法容纳必要证据与完整校验要求，进入分批降级，不能通过删除关键要求强行发送。

预算应区分服务的请求体大小限制、输入 token 限制和上下文限制；涉及上下文上限时，同时为输出预留空间。70% 是配置示例，不是通用保证。

设计目标是在发送前主动控制纠错请求大小，避免依靠线上超限或测试偶然发现问题。

## 3. 超限时降级，避免直接终止（后续优化）

若当前路径在本地拦截后直接报错，可增加以下降级策略：

- 按条款分批让模型重新生成，每批单独校验引用。
- 只重试校验失败的条款，保留已经通过校验的条款。

针对条款数量不一致的情况，例如预期 18 条、实际返回 24 条，分批处理有助于逐条对齐，定位漏识别、重复拆分或重复输出的原因，不能仅凭数量自动删改条款。

## 4. 从源头降低纠错概率（后续优化）

- 要求模型输出引用时带原文片段位置，例如 offset 或段落 ID。
- 引用定位优先使用 ID / 位置匹配，减少格式差异造成的文本匹配失败；同时校验位置有效性及引用与原文的一致性，不能仅有 ID 就认定引用正确。
- 引用校验失败时，先尝试本地确定性修复，例如空白、标点归一化后重新匹配，再决定是否调用模型。
- 本地修复不能改变引用语义；若归一化后出现多个候选位置，应保留歧义并进入后续处理，不能擅自选择。

## 5. 可观测性

记录以下信息：

- 首轮请求大小。
- 校验失败的原始响应大小。
- 压缩后的错误摘要大小。
- 纠错请求大小。
- 触发本地拦截时，请求各组成部分的大小及占比。
- 发生的裁剪和降级动作。

大小记录注明单位及 token 估算方式。通过这些数据区分原始证据、错误反馈、指令等部分的膨胀来源，并评估摘要压缩与分批降级的效果。

## 建议落地顺序

1. 先实施错误摘要与显式预算，直接控制纠错请求膨胀。
2. 补齐日志与埋点，验证预算分配和压缩效果。
3. 再实施按失败条款分批重试与引用定位 / 本地修复，进一步降低失败率和额外调用量。

其中，第一阶段即需明确“必要内容仍超预算”时的处理状态；分批降级能力尚未实现前，应返回明确原因，不得假称已自动恢复。
